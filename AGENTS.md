# AGENTS

Правила для AI-агентов и контрибьюторов, работающих с этим репозиторием.
Монорепо: `apps/backend` (NestJS + TypeORM), `apps/frontend` (Nuxt 3 / Vue), `packages/contracts` (общие контракты backend/frontend). Менеджер пакетов — pnpm, оркестрация — turbo.

## Коммиты

- Conventional commits, сообщения **на русском языке**. Формат: `тип: описание` (например `feat: добавить групповые чаты`).
- Типы: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`.
- Без строки `Co-Authored-By`.

## Changelog

- Значимые изменения (поведение системы, конфигурация, интеграции, запуск, эксплуатация, безопасность, документация) сопровождать обновлением `CHANGELOG.md`.
- Если меняется код, env-шаблоны, инструкции по запуску или публичная документация — проверить, нужно ли обновить `CHANGELOG.md`. Без этого задачу не считать завершённой без явной причины.

## Гигиена репозитория

- Не коммитить секреты, реальные env-файлы, логи, приватные заметки и локальные рабочие артефакты.
- При риске утечки секрета агент обязан явно указать на это в результате работы.

## Деплой

- Не деплоить изменения и не перезапускать production/preprod-процессы вручную без отдельного явного запроса.
- Деплой выполняется через push ветки: CI/CD сам собирает и доставляет изменения.

## Документация

- При изменении поведения проекта обновлять релевантные разделы `README.md`.
- Новые конфигурации, переменные окружения и сценарии запуска отражать в документации.

## Архитектура API

- Все API-endpoint'ы реализуются только в `apps/backend`. Фронтенд обращается к ним напрямую из страниц/компонентов или через `services`, если без этого появляется повторяемая логика.
- `utils` использовать только для чистых вспомогательных функций без сетевых запросов и transport-логики.
- Общие контракты между `apps/backend` и `apps/frontend` хранить в `packages/contracts`: shared `enum`, API DTO/response types, доменные metadata-константы. Не класть туда TypeORM entity, Nest service-логику, store-структуры и app-specific UI-константы.

## Типобезопасность

- Для фиксированных наборов значений использовать `enum`, а не разрозненные строковые литералы.
- Не использовать `any` и `unknown`: описывать точные типы, `union`, `generic`, доменные интерфейсы и явные JSON-типы.
- `enum` не хранить в `types`-файлах — выносить в `enums`-модули рядом с доменом; общие `enum` держать в общем `enums`-каталоге приложения.

## Стили (frontend)

- Эталон вёрстки и правила интерфейса — `docs/design-system.md`. Новые разделы верстать по нему.
- В Vue/Nuxt компонентах и страницах по умолчанию использовать `scoped`-стили. Нескоупленные стили допустимы только для глобального эффекта или переопределения внешней библиотеки.
