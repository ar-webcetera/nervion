# CRM API для интеграций

Все запросы отправляются на адрес вашего backend с префиксом `/api/crm`.
Интерактивная документация с полями запросов — `/api/docs`, OpenAPI JSON —
`/api/docs-json`.

## Авторизация

Создайте API-токен в профиле администратора (или авторизованным запросом
`POST /api/api-tokens` с телом `{"name":"Интеграция CRM"}`). Токен показывается
один раз. Храните его на сервере интеграции, не в коде формы сайта.

Передавайте заголовки:

```http
Authorization: Bearer <API_TOKEN>
Content-Type: application/json
```

Cookie и вход через браузер для последующих запросов не нужны. Токен действует
с правами владельца, а не только в CRM: используйте отдельный токен для каждой
интеграции и задавайте срок действия через `expires_at`. CRM доступна только
токенам администраторов; актуальная роль проверяется при каждом запросе.
Удаление токена через `DELETE /api/api-tokens/:id` прекращает доступ.

## Компания → контакт → сделка

1. `POST /api/crm/companies` — создать компанию. Обязательно только `name`.

```json
{
  "name": "Альфа",
  "legal_name": "ООО Альфа",
  "inn": "1234567890",
  "website": "https://example.com"
}
```

Успешный ответ `201` содержит созданную компанию и её `id`.

2. `POST /api/crm/contacts` — создать контакт клиента. Подставьте полученный
   `id` компании в `company_id` (ниже условный пример `42`). Обязательно только
   `name`; контакт может существовать без компании.

```json
{
  "name": "Иван Петров",
  "company_id": 42,
  "position": "Директор",
  "phone": "+7 900 000-00-00",
  "email": "ivan@example.com"
}
```

Ответ `201` содержит контакт и его `id`. Контакт — человек на стороне клиента,
**не пользователь трекера**: учётная запись и доступ к системе не создаются.

3. `POST /api/crm/deals` — создать сделку. Подставьте реальные идентификаторы
   компании и контакта из предыдущих ответов (ниже условные `42` и `57`).

```json
{
  "title": "Разработка сайта",
  "company_id": 42,
  "contact_ids": [57],
  "primary_contact_id": 57,
  "amount": 150000.50,
  "source": "Форма сайта",
  "expected_close": "2026-12-01"
}
```

Ответ `201` содержит карточку сделки с `id`, связями, задачами и историей.
Достаточно отправить `{"title":"Новая заявка"}`: ответственный — владелец
токена, этап — «Новая заявка», сумма не указана. `amount` передаётся числом
в рублях с максимум двумя знаками после запятой; в ответе — десятичной строкой
либо `null`. Основной контакт должен входить в `contact_ids`.

## Чтение и изменения

| Метод | Назначение |
| --- | --- |
| `GET /api/crm/options` | Компании, контакты, этапы, администраторы, проекты и источники |
| `GET /api/crm/deals/:id` | Полная карточка сделки |
| `PATCH /api/crm/deals/:id` | Изменить переданные поля, связи или этап |
| `PATCH /api/crm/companies/:id` | Изменить компанию |
| `PATCH /api/crm/contacts/:id` | Изменить контакт |
| `GET /api/crm/board` | Колонки с карточками, общими суммами и счётчиками |
| `GET /api/crm/columns/:id?offset=30&limit=30` | Следующая страница колонки |
| `POST /api/crm/deals/:id/tasks` | Создать общую коммерческую задачу: `title`, опционально `planned_date`, `responsible_id` |
| `POST /api/crm/deals/:id/task-links` | Привязать существующую задачу по `task_id` |
| `POST /api/crm/deals/:id/comments` | Добавить комментарий в поле `message` формата Tiptap JSON |
| `POST /api/crm/deals/:id/project` | Создать проект из успешной сделки; повторный вызов возвращает связанный проект |

Фильтры доски: `search`, `company_id`, `contact_id`, `responsible_id`, `source`,
`quick` (`all`, `mine`, `overdue`, `unscheduled`), `today` (`YYYY-MM-DD`).
Размер страницы `limit` — от 1 до 100. Идентификаторы этапов берите из `options`;
при переводе в проигранный этап обязательно передавайте `loss_reason`.

## Ошибки и повторы

- `400` — неверные поля, несуществующая связь или отсутствующая причина проигрыша.
- `401` — отсутствующий, неверный, истёкший либо отозванный токен.
- `403` — владелец токена не администратор.
- `404` — запрошенная сущность не найдена.

Создание компаний, контактов и сделок не выполняет автоматическую дедупликацию
и не поддерживает `Idempotency-Key` в первой версии. Сохраняйте возвращённые
идентификаторы на стороне интеграции и используйте `PATCH` для обновлений.
После неоднозначного сетевого сбоя не повторяйте создание вслепую: сначала
проверьте результат. Повторобезопасность создания проекта — отдельное исключение.
