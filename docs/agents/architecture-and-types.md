# Архитектура API и типы

## API и общие контракты

- Все API endpoints реализуйте только в `apps/backend`.
- Frontend обращается к API напрямую из страниц/компонентов или через
  `services`, если без сервиса появляется повторяемая логика.
- `utils` используйте только для чистых вспомогательных функций без сетевых
  запросов и transport-логики.
- Общие контракты backend/frontend храните в `packages/contracts`: shared
  `enum`, API DTO/response types и доменные metadata-константы.
- Не помещайте в `packages/contracts` TypeORM entities, Nest service-логику,
  store-структуры и app-specific UI-константы.

## Типобезопасность

- Для фиксированных наборов значений используйте `enum`, а не разрозненные
  строковые литералы.
- Не используйте `any` и `unknown`: описывайте точные типы, unions, generics,
  доменные интерфейсы и явные JSON-типы.
- Не храните `enum` в `types`-файлах. Выносите их в `enums`-модули рядом с
  доменом; общие `enum` держите в общем `enums`-каталоге приложения.
