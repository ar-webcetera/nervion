# Голосовая связь в SaaS

Голосовые комнаты работают через общие backend и PostgreSQL. Флаг `voice`
должен быть явно включен у клиента. В режиме read-only список комнат доступен,
создание комнат, вход в звонок, микрофон и демонстрация экрана запрещены.

## Изоляция и доступ

Ключ медиакомнаты состоит из UUID клиента и числового ID комнаты. Транспорты,
producer и consumer дополнительно привязаны к пользователю и конкретному
Socket.IO-соединению. Знать чужой идентификатор недостаточно для доступа.

Вход разрешен только активному администратору или сотруднику из списка
участников комнаты. На каждой команде повторно проверяются закрепленный
hostname, JWT, membership, роль, флаг функции и состояние оплаты. Реплика,
владеющая SFU, выполняет собственную проверку живого сокета. Внутреннее RPC
не заменяет авторизацию. Клиент не передает tenant, пользователя или владельца SFU.

Запросы к рабочей базе выполняются в новой tenant-транзакции. Долгоживущие
таймеры не используют EntityManager завершенного HTTP-запроса.

Активные соединения перепроверяются каждые 5 секунд. Удаление участника,
блокировка клиента, read-only и отключение функции закрывают медиасессию.
При зависании проверки более 20 секунд комната закрывается принудительно.
Это ограничение защищает от сохранения доступа при недоступной базе, но
не означает мгновенную остановку медиапакетов в момент изменения membership.
Таймеры требуют работающего Node event loop. Контролируйте его задержку и
завершайте весь backend-процесс вместе с дочерним mediasoup worker при
зависании процесса. В production настройте liveness probe и process-group
termination, а не только перезапуск HTTP-обработчика.

## Несколько backend-реплик

Redis adapter доставляет события Socket.IO, но не переносит mediasoup router,
транспорты и медиапакеты между процессами.

Для каждой комнаты Redis хранит владельца SFU. Первая реплика, получившая
вход в свободную комнату, приобретает lease на 30 секунд и создает локальный
router. Другие реплики направляют signaling владельцу через закрытый Redis
Pub/Sub. Браузер остается на исходном backend. Sticky routing по клиенту не
нужен при транспорте WebSocket.

Lease обновляется примерно каждые 5 секунд. При ошибке Redis или отсутствии
подтвержденного продления 20 секунд владелец закрывает медиакомнату. Команды
одной комнаты выполняются последовательно. Повторный внутренний RPC с тем
же ID не создает второй медиаресурс. Таймаут команды составляет 10 секунд,
клиентского ожидания ответа 15 секунд.

После аварии владельца звонок нужно открыть повторно. Живое перемещение
звонка между SFU не реализуется: другой router не имеет старых DTLS/ICE-сессий.
Новая комната может появиться после истечения старого lease. При плановом
обновлении процессы корректно закрывают комнаты и освобождают владение.

В комнате не больше 50 одновременных участников. Участник может создать один
отправляющий и один принимающий транспорт, по одному микрофону и экрану.
При увеличении нагрузки добавляйте backend-реплики с собственными адресами
медиа. Одна комната остается на одном worker. Большие конференции требуют
отдельного проектирования нескольких router и нагрузочного теста.

## Сеть и переменные окружения

Все реплики используют общий `REDIS_URL`, JWT-настройки, platform database и
data shards. Redis должен быть закрыт от интернета, защищен ACL и TLS между
хостами. Сигнальные сообщения содержат заголовки авторизационной сессии.
Не включайте запись payload Redis-команд или Socket.IO в доступные пользователям логи.

| Переменная | Значение |
| --- | --- |
| `MEDIASOUP_ANNOUNCED_IP` | Публичный адрес конкретной медиареплики, доступный браузерам |
| `MEDIASOUP_LISTEN_IP` | Локальный адрес прослушивания, по умолчанию `0.0.0.0` |
| `MEDIASOUP_MIN_PORT` | Начало диапазона UDP/TCP, по умолчанию `40000` |
| `MEDIASOUP_MAX_PORT` | Конец диапазона UDP/TCP, по умолчанию `49999` |
| `MEDIASOUP_ICE_SERVERS` | STUN URL через запятую или JSON-массив ICE servers; пустое значение отключает STUN |
| `MEDIASOUP_TURN_URLS` | TURN URL через запятую, например `turns:turn.example.test:5349` |
| `MEDIASOUP_TURN_SECRET` | Общий секрет backend и coturn, не меньше 32 символов |
| `MEDIASOUP_TURN_TTL_SECONDS` | Срок временного TURN-доступа, 600-86400 секунд, по умолчанию 86400 |

В production SaaS пустой или loopback `MEDIASOUP_ANNOUNCED_IP` останавливает
запуск. Reverse proxy передает `Host`, `Origin`, cookie и WebSocket upgrade
без изменения. HTTPS обязателен для микрофона и демонстрации экрана вне localhost.
API и WebSocket используют домен клиента, без общего стороннего домена с cookie.

Указанный диапазон UDP/TCP открывается на каждой медиареплике. Если несколько
реплик имеют один IP, назначьте им непересекающиеся диапазоны и соответствующий
NAT port mapping. Обычный HTTP reverse proxy не проксирует WebRTC-медиа.

Для корпоративных сетей нужен TURN. В coturn включите REST authentication
(`use-auth-secret`, соответствующий `static-auth-secret`), realm, сертификаты,
лимиты полосы и выделений. Запретите TURN-доступ к внутренним адресам и
loopback. Пример URL с TCP: `turns:turn.example.test:5349?transport=tcp`.
Backend выдает временные HMAC-SHA1 credentials, привязанные к клиенту и
пользователю. Сам общий секрет браузеру не передается. Звонок дольше срока
TURN-доступа нужно переподключить; выберите срок с учетом рабочих созвонов.
Legacy JSON-конфигурация `[{"urls":"turns:host:5349","username":"name","credential":"password"}]`
остается доступна без SaaS. В SaaS статические TURN-настройки в
`MEDIASOUP_ICE_SERVERS` запрещены. Используйте отдельные переменные TURN для
выдачи временного доступа, а не общий постоянный пароль для всех клиентов.

## Приемка перед production

1. Включите `voice` на двух тестовых клиентах. Создайте комнаты с одинаковыми ID.
2. Откройте браузеры через разные backend-реплики. Проверьте звук, mute и экран.
3. Попробуйте чужие transport/producer/consumer ID и JWT другого поддомена.
4. Удалите участника комнаты, отзовите membership, включите read-only и отключите флаг.
5. Остановите Redis или SFU-владельца. Старый звонок должен прекратиться, новый
   после истечения lease должен работать на другой реплике.
6. Проверьте TURN из сети с запрещенным прямым UDP и TCP к медиапортам.
7. Убедитесь, что после выхода, ошибки подключения и отказа в разрешении
   микрофона индикаторы захвата микрофона/экрана в браузере выключаются.

Unit-тесты изоляции, lease и TURN-конфигурации находятся в `apps/backend/src/voice`.
Они не заменяют сквозной тест WebRTC на двух хостах и реальной сетевой конфигурации.

Архитектура распределения комнат описана в
[документации mediasoup](https://mediasoup.org/documentation/v3/scalability/).
Настройки временной TURN-аутентификации приведены в
[конфигурации coturn](https://github.com/coturn/coturn/blob/master/examples/etc/turnserver.conf).
